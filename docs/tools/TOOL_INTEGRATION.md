# PURSUE OS — Tool Integration

> **Source:** PURSUE OS master handoff (authoritative). Restored 2026-08-09.
> **Category:** A — Authoritative tool-integration strategy.

## Locked Strategy

- Treat the investigation domain broadly: support as much of the investigator workflow as practical.
- **Integrate existing tools where appropriate** — not every tool must be built by PURSUE.
- **Provide official tools where necessary.**
- **Ensure major frameworks are supported.**
- **Avoid reinventing mature tools** without reason.
- Modular architecture; the OS should feel like an investigator's complete workstation.
- Hardware-specific limitations remain the user's responsibility.

## Curated Defaults

- Initial default tools are **curated**: approximately 5–7 useful tools per use case (OSINT, SOCMINT, GEOINT, CTI, DFIR, infrastructure, media, etc.), not a dump of every available tool.
- Users can install more.

## Implementation-Defined

The concrete tool list per use case, integration mechanism, and packaging are implementation-defined (Category B), locked during the tooling phases. Not implemented in the current foundation.
